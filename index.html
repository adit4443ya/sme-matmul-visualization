Why the four tiles are interleaved

  
ZA is one flat array of vectors. The four fp32 tiles are not stacked in it — they are woven together, one vector each in rotation. At SVL = 128 that is 16 vectors of 16 bytes, four per tile.

  

    

    

      

        
        
      

      

      
Addressing the same storage along two axes is also what makes transpose free — written by row, read back by column, with no permute and no element moves. Phase 1 above walks that through element by element.

    

  






  
Only ZA0.S ever fills. This kernel uses one of the four fp32 tiles, which is why a tuned kernel accumulates a 2×2 block of tiles instead — that doubles arithmetic intensity from 8 to 16 MACs per element loaded.

  
Only two vector registers are live in the k-loop, because C is accumulating in ZA rather than occupying 24 accumulator registers the way a NEON 8×12 kernel must.

  
The edge patches run the same instruction as the full ones, with shorter predicates. Skip to patch (8, 8) to see both masks go short at once. There is no tail loop anywhere in the kernel.
